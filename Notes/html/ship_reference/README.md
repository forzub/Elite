# Elite 3126 — HTML-справочник кораблей

Открыть `index.html` обычным браузером. Сайт полностью статический и не требует HTTP-сервера.

Одна страница `index.html`, вид задаётся адресом (перезагрузка и «назад» его сохраняют, прокрутка
запоминается для каждого вида):

- **Каталог** (`index.html`): карточки кораблей (картинка + название), сгруппированные блок → производитель →
  роль; на карточке класс, шифр модели и полоска «сколько моделей модулей готово». Поиск сверху.
- **Корабль** (`?ship=ID`): слева краткое описание (назначение, класс, роль, блок, производитель, особенности;
  изображение корабля перетаскивается прямо на картинку), справа функциональная схема: корпус и секции
  `<шифр>A1…A12`, в каждой карточки модулей с галочкой «модель готова». Галочка общая для модуля:
  один и тот же модуль на разных кораблях отмечается один раз. Ниже свёрнутый полный инженерный паспорт.
- **Модуль** (`?ship=ID&part=ID`): что это и назначение, физические характеристики, геометрия, промт для
  генератора эскиза (собирается из паспорта; правку можно сохранить или вернуть автоматический), замены,
  группа эскизов: перетаскивание файлов, вставка Ctrl+V или выбор файлов. Эскиз открывается в окне с полем
  заметок и кнопкой «Пересохранить» (Ctrl+S), листанием, скачиванием и удалением.
- **Покрытие флота** (`?view=coverage`): матрица блок × роль.

`ship.html?id=ID` (старые ссылки) переадресует на `index.html?ship=ID`.

**Шифр модели** (число перед «A» в кодах секций) - поле `model_code` паспорта, свой у каждого корабля
(Cobrett-I N1 = 35, остальные 36…72). Канон: `tools/colonization_lab/canon/ship_passports_3126.json`
(21 паспорт); у 17 предложений справочника шифры в `tools/build_proposals.js` (`PROPOSAL_MODEL_CODES`).

## Где хранятся эскизы, заметки и отметки

Статическая страница сама в файлы писать не может, поэтому:

- всегда: в браузере (IndexedDB) - переживает перезагрузки, но живёт только в этом браузере;
- кнопка **«Подключить папку»** (Chrome / Edge): выберите `Notes/html/ship_reference/workshop`, и всё
  зеркалируется туда - `workshop.json` (галочки, правки промтов, список эскизов с заметками),
  `sketches/<id модуля>/…`, `ships/<id корабля>.…`. Тогда эскизы попадают в git и видны другим. При
  следующем открытии браузер может попросить подтвердить доступ (кнопка «Переподключить папку»).

`node tools/render_check.js .` - проверка данных (шифры уникальны, модули разрешаются, у классов и категорий
есть названия).

## Покрытие флота и предложения справочника

Главная страница без параметра (`index.html` или `index.html?view=coverage`) открывает **«Покрытие флота»**:
матрица блок × роль (● есть паспорт, ◆ добавлено справочником, ◐ роль закрывается чужим корпусом), счётчик
«сколько моделей рисовать» (большие корпуса, варианты, малые аппараты) и список новых деталей.

Записи со `status: "PROPOSAL (reference)"` добавлены в `data.js` вручную, а не из канона
`tools/colonization_lab/canon/*`. Это 17 паспортов (1 новый корпус ТС-6, 13 вариантов существующих корпусов, 3 малых аппарата)
и 2 детали (`srw.reactor.sr26`, `kern.mine.cutter`). У каждой такой записи есть блок `reference`: исходный корпус варианта,
заметка о переделке, взаимозаменяемость, баланс мощности и охлаждения по правилам `ship_designer.py` и открытые вопросы.
Матрица хранится в `data.js → coverage`. Если `data.js` перегенерируют из канона, эти записи нужно сохранить или перенести в канон.

## Proposal ships (2026-11-06)

`tools/build_proposals.js data.js` re-adds the "PROPOSAL (reference)" ships, parts and the coverage matrix (idempotent: strips earlier ones first) - run it after any regeneration of `data.js` from the canon. Run from the reference folder: `node tools/build_proposals.js data.js`.
