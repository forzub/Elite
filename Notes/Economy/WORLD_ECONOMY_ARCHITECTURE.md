# Архитектура мировой экономики

Статус: PROPOSAL, принято пользователем как рабочая схема 2026-11-03 (запасы / потоки / решения; логистика между политикой и результатом). Реализация: офлайн-модель `tools/colonization_lab/world_economy.py` (+ `demography.py`, `logistics.py`), runtime пока не переписан.

## 1. Запасы, потоки, решения

```text
            ┌──────────────── ФИЗИЧЕСКИЙ МИР (почти неизменное) ───────────────┐
            │ звёзды, тела, месторождения, расстояния, сеть маяков, правило прыжка │
            └───────────────────────────────┬───────────────────────────────────┘
   STOCKS (что есть)              FLOWS (что движется)              DECISIONS (кто решает)
   население, поселения,          грузы, топливо, запчасти,         государство, корпорация,
   ресурсы, шахты, заводы,        люди, деньги, помощь,             военное командование,
   топливо, товары, инфра-        военное снабжение, корабли        банк, местная власть,
   структура, корабли, деньги                                       политическая фракция
                                    │
                LOGISTICS = обязательный фильтр (провозная способность)
                                    │
                         EVENTS / EFFECTS (журнал причин)
```

Политика, экономика и война — не отдельные модули с независимыми числами, а разные **решатели** над одними запасами и потоками. Один и тот же завод работает на гражданского или военного заказчика; одна и та же верфь строит фрейтер или эскорт.

## 2. Конвейер решения

```text
POLITICAL DECISION → что реально существует → что реально выделили → LOGISTICS CAPACITY
→ задержки / потери / перехват → что реально доставлено → может ли получатель использовать → эффект
```

Одинаково для торговли, военной помощи, помощи при катастрофе, колониальной поддержки и промышленных инвестиций. В модели: `SupportProgram` (обещано → выделено → отправлено → прибыло → освоено), потоки с каналом и маршрутом, флот из потоков.

## 3. Уровни симуляции и идентичность

| Уровень | Шаг | Что | Единица |
|---|---|---|---|
| Strategic (офлайн-лаборатория + редкий тик) | год / месяц | демография, мотивы, войны и союзы, строительство, верфи | политии, активы, когорты |
| Operational (runtime вне пузыря игрока) | день / час | запасы рынков, отправки (виртуальный конвой по расписанию), контракты, распределение флота, перехваты | Shipment, ShipInstance (агрегированно) |
| Physical (пузырь игрока) | кадр | конкретные корабли, груз, трафик, стыковка, бой | материализованный ShipInstance |

`ShipInstanceId` существует всегда (реестр); уровень меняет только представление. Так уже работает трафик дока: оболочка ↔ полный корабль с тем же EntityId.

## 4. Минимальный набор первичных данных

Нельзя вычислить — значит, вход (`canon/*.json`):

1. Физика: системы, тела, месторождения (`endowment.py` по каталогу), сеть маяков и правило прыжка.
2. Рецепты 15 товарных категорий (входы, труд, энергия) — `canon/commodities.json`.
3. Классы кораблей: физика + экономика — `canon/ship_economics.json`.
4. Три якоря валюты: реакторное топливо 600 Cr/кг, зарплата пилота 4 000 Cr/мес, «прыжок = 2.5 × внутрисистемное плечо».
5. Население и его эпохи — `canon/population_history.json` (AUTHOR_TARGET + PROPOSAL-эпохи), потребление на душу.
6. Акторы: владение, режим, отношения (`world.json`), доктрины безопасности (`canon/polity_economy.json`).
7. Юрисдикции: пошлины, легальность по семействам режимов (`commodities.json → regime_family`).

Выводится всё остальное: производство, спрос, импорт/экспорт, цены, грузопотоки, флот, верфи, топливо, бюджеты обороны, маяки, уязвимости, сценарии.

## 5. Как модель считает баланс 3126 (`world_economy.py`)

1. **Население и расселение.** Из `demography.py`: численность, ярусы жилья (поверхность / подземелья / выработки в лунах / астероиды / цилиндры / кольца / аванпосты), сумма сходится с населением; города — столица, крупные, промышленные, шахтёрские, порты, базы, наука (`canon/settlements.json` + Ципф).
2. **Спрос** по 15 категориям: душевое потребление, строительство и поддержание хабитатов, энергия населения (14 кВт/чел.), запасы боеприпасов из бюджета обороны, топливо флота.
3. **Своё производство** — доля спроса, которую позволяют эндаумент и технологии; рецепты тянут вход вверх по цепочке (руда → металл → машины).
4. **Межзвёздные потоки**: дефицит закрывается самым дешёвым доставленным источником по реальной сети (стоимость тонны из `logistics.py`); навал — только при причине (нет своего источника или свой дороже); враждебным парам — реэкспорт через нейтрала (+25 %).
5. **Баланс**: `производство + импорт = потребление + экспорт + потери + изменение запаса` (проверяется для каждой политии и категории; груз из воздуха не появляется).
6. **Инфраструктура** из установленных мощностей: объектов = max(выпуск, домашний рынок + экспортный завод) ÷ (мощность × 0.85); экспортный завод строится с подключения к сети (2 %/год от домашнего выпуска, до ×3; сетевое топливо — под спрос сети), плюс строящаяся очередь. Торговля не создаёт мощности: экспорт ≤ установленного (проверка `exports_within_installed_export_capacity`). У каждого объекта — работники, мощность, оборудование, износ → запчасти. Имена только у крупных/стратегических.
7. **Флот из потоков**: судов = т/год ÷ (полезная загрузка × рейсов в год) + резерв + ремонт; плюс челноки, буксиры, газовые танкеры, курьеры, сервис.
8. **Верфи**: новые корпуса = списание + потери + рост; без своих верфей — крупнейший партнёр с верфями.
9. **Топливо**: реакторное (энергетика, отрасли, флот) и заряд прыжка (рейсы, патрули, курьеры): своё / импорт / резерв / депо.
10. **Оборона**: доля выпуска из доктрины и данных; силы — только из 15 задач (линейные корабли — из задачи сдерживания); остаток корабельной статьи — боезапас, запасы, сенсоры, ремонт, обучение, резервы, базы, ПАО/ПРО, НИОКР, мобилизация, консервация, резерв бюджета.
11. **Маяки и трассы**: мост-маяки, маяки узлов, станций, ретрансляторы трасс, военные, удалённые научные; классы трасс trunk / secondary / feeder.
12. **Уязвимости и сценарии** — через ту же систему (см. POLITICAL_ECONOMY.md).

Проверки `--check`: население в авторских диапазонах; расселение сходится; тождество баланса; нет отрицательных запасов; инфраструктура покрывает выпуск; потоки ≤ провозной способности; топливо покрыто; замена флота ≤ выпуск верфей + импорт; статусы; два одинаковых прогона.

## 7. Порядок реализации

1. ✅ Логистический эталон (`logistics.py`, `ship_economics.json`).
2. ✅ Демография под авторский масштаб (эпохи, `calibrate_population.py`).
3. ✅ Баланс мира 3126 (`world_economy.py`), справочник Lore.
3a. ✅ Пространственный слой (`world_sites.py`): хабы, фронтиры, право, связь, пассажиры, возраст флота; карты (первый видимый шаг) — `WORLD_SITES_AND_INFORMATION.md`.
4. Runtime: персистентный реестр ShipInstance / агрегатов (диск), рынок Сола с запасами, контракты-контейнеры C20, сборы.
5. Runtime: трафик хаба из потоков (поток + наличие кораблей + расписание) вместо заданных 4 Cobrett; виртуальные отправки и материализация в пузыре игрока.
6. Runtime: маяки как объекты (транспондеры, картина трафика, задержка света вне покрытия), ошибка выхода прыжка.
7. Банк, кредиты, стоянка; астероидная база игрока; внимание государства.
