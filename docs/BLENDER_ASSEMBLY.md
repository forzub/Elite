# Сборка корабля в Blender со ссылками на модули

Решение принято 2026-11-14, пока автора не было («решение по вопросам — за тобой»). Схема проверена без интерфейса
на Blender 5.0.1: `tools/blender/make_demo_assembly.py` → `assets_source/models/ships/blender_demo/`. Сцену сам
редактор открыл, проверил и собрал в `.elmodel`, а игра пакет нарисовала.

## 1. Что ставится

- **Дополнение** `tools/blender/elite_tools.py`: Edit → Preferences → Add-ons → Install from Disk. Появится панель
  **Elite** в боковой полосе 3D-вида (N).
- **Библиотека модулей** (с 2026-11-14, MESH_EDITOR_SPEC 17) — **файл на модуль**, его пишет меш-редактор
  кнопкой «Построить скорлупу» / «Скорлупы всех модулей» (шаг 1):

  ```
  assets/compiled/<раздел>/<id>/<id>.blend
    коллекция "<id>"        ассет: скорлупа LOD0 (объект на звено "<id>.<звено>") + пустышка "<id>.mount" в начале
                            координат = точка установки; elite_part = "<раздел>/<id>"
    коллекция "<id>.LOD1…3" скорлупы дальних LOD (выключены, в ассет не входят)
    коллекция "<id>.hits"   хитвалумы элементов (пустышки CUBE, elite_hit = элемент), скрыты
    материалы               из глобальной библиотеки (Principled BSDF, elite_material = id)
  assets/compiled/<раздел>/<id>/shell/LOD<N>/<звено>.obj   те же скорлупы для сборки пакета
  ```

  В Blender: Edit → Preferences → File Paths → Asset Libraries → добавить `D:/__elite/work/assets/compiled`
  (назвать «Elite»). Все модули видны в Asset Browser; их перетаскивают в сцену, или «Поставить модуль» со свойством
  сцены `elite_library` = эта папка. У перетащенного экземпляра `elite_part` подставляется из коллекции при экспорте.
  Модуль в сцене корабля **связан** (link), а не скопирован: после перестройки скорлупы корабль видит новую.

  Старый общий `parts_library.blend` (`build-library`) ещё работает, но больше не нужен.

## 2. Сцена корабля

| Что | Как в Blender | Что видит редактор |
|---|---|---|
| Корпус, рама, обшивка | обычные меши; имя объекта = имя детали | части; объём или лист проверяет шаг 1 |
| Модуль (оборудование, позже рама и обшивка) | перетащить из Asset Browser или «Поставить модуль»: пустышка-экземпляр коллекции модуля, `elite_part = "equipment_ship/<id>"`; начало пустышки = точка установки модуля | ссылка (фиолетовая); сетка модуля **не** экспортируется: берётся проверенная сетка из его карточки |
| Иерархия | Blender parent (Ctrl+P, *Keep Transform*) | дерево в шаге 2, линии при разносе |
| Хитвалум | «Хитвалум по выделенному»: пустышка CUBE, `elite_hit = "<узел>"`, `elite_shape = box/cylinder`; полуразмер — масштаб пустышки; цилиндр: радиус — масштаб X, полувысота — масштаб Z | шаг 3, голубые рамки |
| Зона | «Красная / Синяя / Зелёная зона»: пустышка CUBE, `elite_zone = keep_out / keep_in / prefer` | шаг 3; в пакете — гнездо `nav_zone:<вид>` |
| Точка крепления | выделить конструкцию и модуль (модуль — активный) → «Точка крепления»: `elite_mount = "<конструкция>:<модуль>"` | шаг 4, оранжевые кубики → структурная связь `equipment_mount` |
| Шов («колбаска») | выделить две детали → «Шов»: пустышка, вытянутая вдоль стыка (масштаб X — полудлина), `elite_seam = "<a>:<b>"` | шаг 4, жёлтые колбаски → связь `weld_seam` |
| Шины | на питающем объекте: `elite_feeds = "service_power:ship_radar ship_laser_L; data:ship_radar"` | шаг 4, цветные линии; в пакете — в `<id>.elassembly.json` |
| Вид / материал / роль детали | свойства `elite_kind` (volume/sheet), `elite_material` (id из глобальной библиотеки), `elite_role` | шаг 1 (вид), шаг 2 (материал, роль) |
| LOD, повреждения | имена `<деталь>__lod1`, `<деталь>__damaged` (MESH_EDITOR_SPEC 9) | `__lodN` → группа LOD N |

Шины: `propulsion_power`, `service_power`, `coolant`, `heat_rejection`, `data`, `fuel`, `jump_charge` (шины каталога
неисправностей, MAINTENANCE_LAYER_DESIGN).

## 3. Экспорт и путь дальше

1. **«Экспорт для Elite (glTF)»** пишет `<сцена>.gltf` + `.bin` рядом с `.blend`, свойства уходят в extras. Сцена
   лежит в папке модели внутри источника, например `assets_source/models/ships/<корабль>/`.
2. **Редактор** (`tools/mesh_editor/MeshEditorGltf.cpp`) переводит glTF в рабочую копию
   `<work>/<раздел>/<id>/gltf/LOD<N>/*.obj` и `scene.json`. Перевод повторяется, только когда .gltf или .bin новее.
3. **Документ сборки** `assembly.json` заводится из `scene.json` при первом открытии. Дальше его правят окна 2–6,
   источник не трогается.
4. **«Сборка» (шаг 6)** пишет `assets/compiled/<раздел>/<id>/`:
   - `<id>.elmodel` + `.lodN.elmesh`;
   - `<id>.elassembly.json`;
   - `ship_asset.json` + `geo/` — промежуточный вид для сборщика.

## 4. Почему ссылка, а не копия

- Модуль проверяется и чинится один раз, в своей карточке; правка сразу доходит до всех кораблей.
- В `.elmodel` v4 нет ссылки на чужой ассет. Поэтому при сборке сетка модуля кладётся в пакет корабля один раз
  (все одинаковые модули — экземпляры одной геометрии), а сама ссылка остаётся:
  - гнездом `kind = "link"` с профилем `"equipment_ship/<id>"`;
  - записью в `<id>.elassembly.json`.

  Когда в v5 появится свой блок для ссылок, игра сможет грузить модуль отдельно.

## 5. Ограничения сейчас

- Только `.gltf` (не `.glb`).
- Хитвалумы и зоны — коробки или цилиндры, повёрнутые как пустышка.
- Анимация из glTF пока не читается: узлы с ключами доходят, но шаг «Подключения и анимация» ещё не сделан.
- Шины задаются строкой, отдельного редактора в Blender нет; удобнее править их в шаге 4 редактора.
