# Скорость по обзору (sensor-limited speed) — предложение

Автор 2026-11-19 (идея из *Objects in Space*): «если лететь через неизвестные участки космоса, то лучше притормаживать,
чтобы получать информацию с радара. 2000 км на наших скоростях — корабль пролетит быстрее, чем компьютер сможет это
обработать».

## Почему это правдоподобно
На 0.9 c корабль проходит 2000 км радара за 7.4 мс — меньше одного оборота радара и одного шага вычислителя. Увидеть
препятствие и затормозить невозможно: обзор «впереди» физически пуст. Капитан, как штурман в тумане, обязан держать
скорость, при которой успевает увидеть, понять и остановиться/отвернуть в пределах видимого (правило «безопасной
скорости», МППСС-6, только в масштабе космоса).

## Модель
Скорость ограничена так, чтобы за время реакции и торможения корабль остался внутри уверенно просмотренной зоны:

    v·t_r + v² / (2·a_b) ≤ k·R

- `R` — дальность обнаружения радаром корабля (паспорт радара, `ShipDescriptor::radarRangeMeters`); нет радара —
  только оптика / пассивные датчики (меньше R);
- `k` ≈ 0.8 — запас (цель малой ЭПР видна не на всей дальности);
- `t_r` — время реакции: оборот радара + обработка + решение автопилота (≈ 1–2 с; хуже у дешёвого вычислителя,
  повреждённого компьютера — `navComputerState`);
- `a_b` — доступное торможение в этом режиме (уровень J-поля или маршевые двигатели).

Отсюда `v_max = a_b·(−t_r + sqrt(t_r² + 2·k·R / a_b))`.

| R | t_r | a_b | v_max |
|---|---|---|---|
| 2000 км | 1.5 с | 10⁶ м/с² (полный J) | ≈ 830 км/с (0.28 % c) |
| 2000 км | 1.5 с | 10⁴ м/с² | ≈ 160 км/с |
| 150 км (без радара, оптика) | 2 с | 10⁴ м/с² | ≈ 33 км/с (было «≈ 40» — это при k = 1; поправлено 2026-11-19 по юнит-проверке) |

## Где действует
- **Неизвестный (не нанесённый на карту) космос**: между известными местами, за пределами обследованных оболочек
  систем, «Жопа мира», подходы к Фортуне, районы после аномалий.
- **Известный космос снимает ограничение** до обычного предела среды: зелёные коридоры, зона маяков, обследованные
  трассы, купленные записи коридоров / навигационные данные (`laneRecords`, банки навигационных данных). Отсюда
  ценность навигационных данных в торговле (F5 «Навиг. данные»): купил съёмку — летишь быстро; нет — ползёшь.

## Кто решает
По принципу иерархии автора: **автопилот / бортовой компьютер сам выбирает режим** — видит, что участок не нанесён,
и сам держит скорость по обзору; пилот видит это на HUD («обзор: 2000 км, скорость по обзору 830 км/с — участок не
обследован»). Ручной полёт быстрее разрешён — на риск пилота (столкновение с тем, чего радар ещё не показал).

## Реализация (после MVP торговли)
1. Признак «участок нанесён» для точки маршрута (коридор / маяк / запись коридора / обследованная оболочка).
2. Ограничение `v_max` в планировщике скорости маршрута (`RouteLegPilot`) и в J-полёте — как ещё одна граница.
3. HUD-строка и разбор на карте маршрута (сколько времени съест медленный участок).
4. Проверка: юнит на формулу; живой прогон через необследованный участок — скорость держится у `v_max`.

## Реализовано 2026-11-19 (минимальный набор)

Статус: SOURCE + UNIT + LIVE PASS (Sol, 300 а.е. / околоземное пространство). Подходы с записью коридора, глубокий
космос и повреждённый вычислитель — только юнит / по коду, живьём не проверялись.

- **Правило** — `src/game/navigation/rules/SensorSpeedRules.h` (чистое, общее): `sensorSpeedLimitMps(R, t_r, a_b, k)` в
  рационализованной форме `2kR / (t_r + sqrt(t_r² + 2kR/a_b))` (то же `v_max`, без потери точности); `k = 0.8`,
  `t_r = 1.5 с`, `3 с` при отказавшем навигационном вычислителе (`navComputerState == 2`, уже реплицируется);
  `sensorRangeM(R) = max(R, 150 км)` — без радара или с коротким стыковочным радаром видит оптика; `chartedBy(...)`.
- **«Участок нанесён»** — из уже существующих данных, новой базы съёмки нет (в порядке проверки):
  1. внутри зелёного коридора `route_zones.json`;
  2. в зоне радара хаба (`route_zones.json → watch.hub_radar_km`, 3000 км) — это и есть «зона маяков» у хабов;
  3. внутри **обследованной оболочки** локальной каталожной системы: `1.5 ×` расстояние её самого дальнего тела от
     звезды сейчас (Sol: 44.8 а.е.). **Прокси**: отдельных «оболочек обследования» в данных нет; каталожная система с
     описанными телами считается обследованной в пределах своих тел;
  4. подходы системы (`approach:<id>`), если корабль несёт годную (не Unknown) запись коридора её оболочки
     (`laneRecords`) и вычислитель жив. **Прокси**: запись снимает предел на всё пространство подходов, не только на
     конус коридора.
  Не нанесены: глубокий космос (места отстойников), подходы без записей, «дальние» системы каталога (Kepler-62),
  каталожные системы за пределами оболочки.
- **Где применяется** — только автопилоты клиента: `RouteLegPilot` (скорость `speed` к цели ограничена ещё одной
  границей, `a_b` = текущий уровень J-поля `limit`) и J-автопилот к телу `BodyAutopilot::stepTransfer` (скорость сближения,
  `a_b` = текущий разгон поля `ramp`). Скорость — относительно цели (хаб / тело), не глобальная. Ручной полёт не тронут.
  Входы (`sensorRangeM`, `sensorReactionS` в `BodyAutopilotShip`) заполняет `SpaceState::applySensorSpeedInputs`
  (`SpaceStateRoute.cpp`) при каждом шаге автопилота; лог `[SensorSpeed]` при смене причины.
- **HUD** — строка под панелью автопилота, когда предел действует: ключ `cockpit.autopilot.sensor_speed`
  (en / ru / zh-Hans / es / ja): «обзор 150.0 км · скорость по обзору 77.94 км/с · участок не обследован».
- **Юнит** — `EliteBodyFlightRulesCheck` (таблица выше, закон `v·t + v²/2a = kR`, предел `kR/t_r`, правило нанесённости):
  PASSED. Таблица: 834.5 / 164.5 / 32.9 км/с (строка 3 исправлена: было «≈ 40», это при k = 1).
- **Живьём** (`D:/tmp/sensorspeed/`): старт `point:300,0,0` (300 а.е., за оболочкой Sol), маршрут к орбите Марса —
  скорость к цели растёт с разгоном поля и держится ровно 77 935 м/с с t+30 с до конца (`far3.log`, `far3_95.png`);
  J-автопилот к Луне оттуда же — 77.61 км/с ровно (`farap2.log`, `farap2_95.png`); старт у Высокого, тот же маршрут —
  «зелёный коридор → зона радара хаба → оболочка системы», ограничения нет, 28 853 км/с на t+60 с (`near.log`,
  `near_80.png`).

### Отклонения и находки
- Корабль игрока — legacy-дескриптор без паспорта (`catalog.passportId` пуст, `catalog.radarRangeMeters = 0`); его
  установленный радар — PPI LCD с `maxRange = 1000 м` (стыковочный). По честным данным `v_max` = 533 м/с — корабль не
  выбрался бы из ненанесённого места. Поэтому нижняя граница дальности — оптика 150 км (`v_max` при полном J ≈ 78 км/с).
  С паспортным радаром 2000 км будет ≈ 832 км/с. Повреждение радара не учитывается (у клиента нет готового признака —
  только состояния модулей).
- Скорость ограничивается относительно цели маршрута, а не «среды» (на HUD глобальная 103 км/с при 77.9 к Марсу).
- Не сделано: разбор времени медленного участка на карте маршрута (оценка в `RoutePlanner` не трогалась — нетривиально:
  нужна нанесённость вдоль всего пути), серверная проверка (автопилоты клиентские — сервер не ограничивает), NPC.
- Вопрос автору: считать ли обследованными каталожные системы без маяков (`systemHasBeacons` = есть места мира);
  сейчас — да, в пределах оболочки тел.

## Решения автора 2026-11-20 (знание космоса)
- **Хорошо обследованы только обжитые системы** и **торговые маршруты** между ними (на них маяки). Сделано:
  оболочка системы снимает предел только у обжитой системы (есть хабы / места мира); пустая каталожная система —
  «известна обрывками», автопилот держит скорость по обзору (`ChartedQuery::inhabited`).
- Всё остальное известно **обрывками**: метеоритные поля, газовые и ледяные облака — в них должны быть **проходы**.
- Источники знания (будущее): **зонд-разведчик**, заранее запущенный искать трассы; **дневники и записи пилотов**,
  открывавших системы; **библиотеки с архивами**.
- **Карта открывается постепенно**; сведения о секторах можно **продавать и покупать** — государству или другим
  игрокам. Под карту выделить отдельное время (дизайн карты ещё не придуман).
- **Предел радара 2000 км автору не нравится** — сильно режет возможности на таких расстояниях, но какое-то
  ограничение должно быть. Пересмотреть модель вместе с картой (варианты — в ответе 2026-11-20: дальний
  навигационный сенсор для крупных тел; жёсткий предел только в опасных зонах — поля, облака; в пустом
  необследованном пространстве — риск, а не потолок).
