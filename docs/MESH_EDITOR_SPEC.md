# Мешэдитор — спецификация (черновик для обсуждения с автором, 2026-11-13)

Статус: ЧЕРНОВИК. Каждое окно обсуждается с автором до кода. Решения автора помечены «(автор)».

## 1. Зачем он нам

Работа с меш-моделями всех объектов игры:
- оборудования кораблей, станций и модулей хабов;
- кораблей;
- модулей станций и хабов, модулей модулей.

Вход — то, что сделано в Blender (автор) или сгенерировано скриптами (Claude). Выход — пакет модели, который **игра
реально читает**: LOD, хитвалумы, физика, элементы и их роли, состояния повреждений, гнёзда, анимация.

Главное требование к новому редактору: с первого среза его результат грузится в игру. Старый редактор умеет много, но
игра почти ничего из его выхода не читает:
- хиты, коллизии и повреждения `.elmodel` не используются;
- корабли каталога рисуются коробками;
- 116 моделей оборудования лежат без дела.

## 2. Переделывать или с нуля (предложение)

- **С нуля:** интерфейс и сценарий работы. Старый — один файл сессии на 12.8 тыс. строк, сжатая страница на 293 КБ;
  автор: «очень неудобно».
- **Переиспользовать проверенное ядро:**
  - двоичный формат (`src/model_asset`, v4; черновик v5);
  - упрощение для LOD (`LodMeshSimplifier`);
  - починку мешей (libigl/Embree);
  - поиск одинаковых деталей (`GeometryInstanceFitter`);
  - чтение OBJ.

## 3. Два вида моделей: деталь и сборка (автор: «использование ссылок выглядит очень разумно»)

- **Деталь** — оборудование, модуль хаба и т. п. Свой файл в собственных координатах:
  - LOD;
  - элементы и их роли;
  - хитвалумы;
  - физика (масса, центр масс, инерция);
  - состояния повреждений;
  - точки подключения (крепление, питание, данные);
  - анимация узлов.
- **Сборка** — корабль, станция, хаб, составной модуль:
  - свой корпус (рама + обшивка = «кожура»), его LOD, броня-хитвалумы, отсеки;
  - гнёзда со ссылками на детали (штатная комплектация).
  - Меши деталей в сборку не копируются.
- **Следствия:**
  - замена оборудования (F7) меняет только ссылку;
  - вдали рисуется корпус + крупные внешние детали, мелочь отсекается по экранному размеру;
  - попадание проходит броню корпуса, потом хитвалумы деталей внутри;
  - сборка может входить в сборку (модуль хаба в хабе).

Порядок работы (автор): «собираем сначала детали каждого с его собственной физикой, потом собираем ссылки в корабль на
раму и обтягиваем обшивкой».

## 4. Хранение на диске

В настройках две папки: источник и результат. Внутри одинаковое деление по разделам:

```
источник/                          результат/
  equipment_ship/<id>/               equipment_ship/<id>.elmodel (+ LOD-файлы)
  equipment_station/<id>/            equipment_station/...
  equipment_hub_module/<id>/         equipment_hub_module/...
  ships/<id>/                        ships/<id>.elmodel   ← корпус + гнёзда + комплектация
  stations/<id>/                     stations/...
  hub_modules/<id>/                  hub_modules/...
```

Папка источника:
- **модель автора** — один файл glTF (из Blender) + текстуры;
- **модель Claude** — много мешей деталей (или тоже glTF);
- в обоих случаях — `asset.json`: раздел, имя, заметки, статус.

## 5. Окно «Открыть» (автор)

- Кнопка «Открыть» → модальное окно с большими кнопками разделов:
  - оборудование кораблей;
  - корабли;
  - оборудование станций;
  - станции;
  - оборудование модулей хабов;
  - модули хабов.
- Раздел → карточки папок. На карточке:
  - снимок модели (редактор рендерит сам);
  - что это (из `asset.json`);
  - где используется — для какого корабля или хаба, по каталогу кораблей и данным хабов;
  - статус готовности: не обработана / в работе / готова / устарела (источник изменился после сборки).
- Клик по карточке открывает модель. Сразу идёт проверка каждого элемента на годность к рендеру (шаг 6.1).

## 8. Изменения источника

- Элемент опознаётся **по имени**, не по номеру.
- При повторном импорте окно разницы: добавлено / удалено / изменено (отпечаток геометрии).
- **Удалён:** всё привязанное (хитвалум, состояния, отметки) становится «сиротами» — перепривязать или выбросить.
  Ничего не теряется молча.
- **Изменён:** его LOD и хитвалумы помечаются «устарело — проверить».
- **Добавлен:** ждёт роли в шаге 6.2.

## 9. Соглашение об именах (одно для Blender и для Claude)

- Элемент: `<имя>`, например `turret_barrel`.
- Состояния повреждения: `<имя>__damaged`, `<имя>__destroyed`.
- LOD внутри одного источника: `<имя>__lod1`, `__lod2` (если делаются вручную; иначе генерируются).
- Роль (необязательно, иначе назначается в 6.2): пользовательское свойство `elite_role` = `body` / `power` / `control` /
  `power_supply` / `control_supply`.
- Ссылка на деталь в сборке: пользовательское свойство `elite_part` = `<раздел>/<id>`.

## 10. Blender (автор: glTF подходит; «там же можно делать и скелетную анимацию»)

**Как работать:**
1. Детали — библиотека ассетов Blender: редактор выгружает готовые детали в библиотечный .blend; браузер ассетов
   Blender показывает их с превью.
2. В сцене корабля:
   - рама и обшивка — обычные меши;
   - детали — экземпляры коллекций из библиотеки (Link) с пометкой `elite_part`.
3. Экспорт: glTF, с «Custom Properties» (extras) и анимацией.
4. Импорт в редактор:
   - узел с `elite_part` → гнездо со ссылкой (его меши не берём);
   - остальное → корпус.
- Небольшое дополнение для Blender (Claude напишет): «поставить деталь из библиотеки», «пометить», «экспорт для Elite».

**Проверено 2026-11-13, Blender 5.0.1, без интерфейса** (`D:/tmp/gltf_test`, скрипт в черновиках сессии):
- Библиотека `parts_library.blend` (radar, turret — коллекции-ассеты). Сцена корабля: frame, skin, три экземпляра по
  ссылке (radar_top, turret_left, turret_right) с `elite_part`, ключи поворота на turret_left.
- В `ship.gltf`:
  - экземпляр — узел с именем, положением и поворотом, `extras: {"elite_part": "equipment_ship/turret"}` и детьми —
    мешами детали;
  - обе турели ссылаются на одни и те же меши (индексы 4 и 5) — копий нет;
  - анимация `turret_leftAction` — канал rotation узла экземпляра;
  - оси переведены в Y-вверх самим экспортёром.
- Вывод: всё нужное для гнёзд и анимации узлов в glTF доходит.

**Анимация:**
- для механики — анимация узлов (деталь движется целиком): турели, створки, опоры;
- скелетная анимация (кости + веса вершин) в glTF тоже есть — для того, что гнётся.
