Structural observations:
- **H — `ActiveFreeFlight` (`GameSimulation.h:230-312`) has about 70 fields** for 7 interleaved sub-machines: ballistic frame, J autopilot, parking orbit, landing module, route leg, take-off, body frame, landing pilot and auto-stabilization. They are switched by booleans (`legActive`, `takeOff`, `bodyFrame`, `localFrame`, `pilotActive`, `landingStarted` ...) and an int `autopilotPhase` with bare values 1..11. There are 37 numeric phase / refusal / reference comparisons in `GameSimulationFreeFlight.cpp` alone. The replicated docs have already drifted: `freeFlightCaptureRefusal` documents codes 1-2 but the code uses 1-9; `freeFlightAutopilotPhase` documents 0-5 but the code uses up to 11 (`DynamicMotionState.h:99-137`). The HUD decodes the codes again (`SpaceStateHud.cpp:1712-1729`). The split is overdue: a `FlightMode` variant (Stabilized{Hub/Orbit/Ground}, Normal{J on/off}, Autopilot{J-transfer, ParkingOrbit, Deorbit, Terminal}, RouteLeg, TakeOff), with each mode in its own unit and enums shared over the wire (`ELITE_WIRE_ENUM_RANGE` already exists).
- **M** — the 70-line header comment of GameSimulationFreeFlight.cpp (lines 1-70) describes three successive architectures ("names above are the older ones"). It should be replaced by one current description in the navigation contract.
- **M** — `SpaceState` is still the client god object: map orchestration, route planning, the zone fines, the DEV script, the HUD. `DynamicMotionState` (the physics state struct) also carries HUD-only facts (ground material, slope, feature, Pe/Ap, drag), which grows every snapshot.
- **M** — the large header-only client bridges (`ClientDetailMapBridge.h` 921 lines, `ClientHubMapBridge.h` 472, `ClientWorldSitesMapBridge.h` 463, `ClientDetailMapTrajectories.h` 218) are compiled into every includer.

## 6. Threading and resource safety

| # | Sev | Finding | Evidence |
|---|-----|---------|----------|
| 6.1 | M | **`ModelAssetGpu` loader thread.** (a) No try/catch around `MeshGPU::prepare(toMeshData(...))`: a `bad_alloc` on the 201k-triangle LOD0 (about 110 MB vertex-expanded) calls `std::terminate`. (b) The worker prepares **every** LOD and geometry eagerly and holds them all in `m_ready` until pumped, so the CPU-side peak is about the whole expanded model, even if the station is never seen. (c) Duplicate work: if `gpuFor` needs a piece the worker is still preparing, it builds it synchronously and the worker's copy is discarded later (`if (slot) continue`). This is correct but wasteful. (d) The instance lives in a function-local static `unordered_map` (`:317`), so the join and destruction happen during static destruction, after the GL context is gone. `MeshGPU` has no destructor (`MeshGPU.h`, no `glDelete*`), so nothing crashes now, but GL objects leak by design. (e) `ModelAssetGpuLibrary::get` is not thread-safe (plain statics). It is only called from the render thread today; that assumption is not documented. | `ModelAssetGpuLibrary.cpp:201-222, 235-313, 315-327` |
| 6.2 | M | **Detached terrain loader threads on the server** (one per body, `std::thread(...).detach()`): no cap, no cancellation, still running at shutdown. The lifetime is safe (the `shared_ptr` is captured) and the acquire/release flag is correct. A body is unavailable ("return false") until its field loads, so landing and contact quietly use no terrain during the first seconds. | `GameServer.cpp:2415-2433` |

## 7. Tests and gates

- **Python gates: 122 pass / 87 fail out of 209** (`check_*.py` in tests/, tools/, src/; exit code != 0). Most failures are stale **token-presence** checks, which grep for literal source strings: model-asset editor version pins ("editor version is not 0.10.73"), `CURRENT_TASK/CURRENT_STATE` stage markers, deleted files (`SystemMapSceneRenderer.inl`, `PredictivePilot.h`, `tests/navigation_guidance/CMakeLists.txt`). - Known non-compiling: `SystemMapBehaviorTests` (abstract mock; ctest runs a **stale binary**) and `LocalPredictedPresentationContractTests` (PROJECT_STATE map-1, baseline reds). A stale binary passing is worse than a red.
- `tools/check_map_architecture.py` crashes (FileNotFoundError on a deleted `.inl`).
