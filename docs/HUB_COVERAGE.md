## Surface settlements

148 public surface sites (planetary_surface_port 98, moon_hub 37, industrial_hub 11, science_hub 2), 13 hidden ones (pirate / smuggler).

What exists: `src/world/celestial/settlements/SurfaceSettlementLayout.h` lays out EVERY surface site from its id (server terrain flattening, landing autopilot pads, renderer): an entrance into the ground, 2-3 small domes, an antenna mast and 1-3 pads (a rock passage + pad on a body under 400 km). The same small layout for a 600-person lab and for a 1.2-billion agglomeration, and the same on airless and atmospheric bodies.

Missing:
- a city of the hub kit on the ground (the author's decision 2026-11-18: «surface settlements = the same hubs on a planet»): the planar generator's map (blocks / streets / zones / landmarks) placed on the terrain - the frozen layout format already fits (the module y = 0 plane -> the local tangent plane at the site), what is missing is the terrain side (flattening per block, the footprint union) and the size rule (the biggest: агломерация «Токио» 1,276,977,164, агломерация «Дели» 616,739,317, агломерация «Шанхай» 402,907,928, агломерация «Сан-Паулу» 297,865,456, агломерация «Мехико» 235,648,471);
- 65 surface sites have ids not starting with `site.` (Earth agglomerations `city.000.*`, plants `plant.*`, ...): `surfaceSettlementBody()` parses `site.%d` only, so the landing autopilot / DEV start cannot address them by id (fix: take the system id from the site's catalog entry instead of the id prefix);
- the recognizable terrain classes the author asked for around settlements (canyon / rift, plain) - FeatureClass has MountainRange, ImpactCrater, Volcano, Lake, IceCap only;
- an atmospheric-body style (Earth / Mars cities are drawn as airless-Moon entrances).
